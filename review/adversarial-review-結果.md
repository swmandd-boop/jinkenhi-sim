## 両方が挙げた指摘

### 1. 老健・起動直後の丸め矛盾クラスタ 〔本夜修正済み〕
- codex F-06 ／ Claude F-01・F-02
- 場面12。「実配置＝基準」を謳う起動直後に、介護職員「0.0 人 不足」の赤表示、
  成立判定「人数が下限を 0.1 人分下回っています」、曲線「職種別基準35.9／配置下限36.0」の
  二重線が同時発生。指標バーは「基準合計との差 ＋0.0／1.00倍」で衝突。
- 根因: `initialRows` が基準を四捨五入（`Math.round(std*10)/10`）し、老健 介護 std=21.905 を
  21.9 に切り下げ。充足判定は生 std と比較するため 0.0048 だけ下回り「不足」に落ちる。
  配置下限は `Math.ceil` 側なので 36.0 に切り上がり、実配置 35.9 と 0.1 差が生じる。
- 修正: ENGINE区間の `initialRows` を CEIL（0.1単位切り上げ）に変更。基準どおりの初期配置が
  各職種で基準以上になり、職種別不足も下限割れも解消。
- 回帰テスト: `tests/initial-roster.test.mjs`（INIT-01／INIT-02、全サービス）。修正前は老健で失敗。

### 2. fit-wage「賃金倍率 ×1.000」なのに正規年収が599.8等 〔未修正・要判断〕
- codex F-05 ／ Claude F-04
- 場面06/08。「入力した基準年収どおりにする」押下後、倍率は ×1.000 表示だが、
  施設長599.8（基準600）・介護369.8（基準370）。
- 根因: fit-wage（UI層）が人件費率を 0.1％刻みに丸めるため実 k≈0.99959。倍率は toFixed(3) で
  1.000 に丸まる。倍率も年収も同一 k から派生しており内部不整合ではないが、「どおり」の文言と
  表示解像度が食い違う。
- 未修正の理由: 直すと「クリーンな％表示」か「厳密な倍率」かの表示方針トレードオフになる
  （E-008 別丸めの論点）。設計・表示方針の判断を伴うため夜間修正の対象外（STOP条項7）。

### 3. 兼務可職種の常勤換算・満額計上（二重計上の疑い） 〔未修正・要判断〕
- codex F-09 ／ Claude F-08
- 機能訓練指導員・介護支援専門員など「兼務可」注記の職種を、基準の単純合計・配置下限に
  独立1.0FTEとして満額加算。必要頭数を過大に、平均年収の成立余地を過小に見せうる。
- 両レビュアーとも「開示済み（主要職種の要約というディスクレーマあり）／疑い」と評価。
- 未修正の理由: 兼務前提の係数化は配置基準の解釈・設計方針そのものの変更（STOP条項7）。

## ダンプ由来の誤検出（矛盾ではない）
- ratioモードで #total（年間人件費総額）は hidden。ダンプが拾う 23791／30864／4951 は
  `loadService` の stale 値で、実使用 total は `rev×ratio/100`。書き出し（場面14）の 4,124万円が正。
  → codex F-01・F-02・F-03・F-07 はこの隠しフィールド由来。ユーザー非表示のため画面矛盾ではない。
- 通所 場面13 で n>std（相談員 基準0.9/正規1.1 等）は、days を 6→5 に変えた際の仕様どおりの挙動。
