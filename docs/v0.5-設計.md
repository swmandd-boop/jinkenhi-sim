## 1. 職種表を3行にする

10行から3行へ。各行に正規・非正規・派遣の3列。

```
職種          基準    正規   非正規   派遣    合計
介護職員      22.6    ○○     ○○     ○○     ○○
看護職員       3.0    ○○     ○○     ○○     ○○
その他職員     5.1    ○○     ○○     ○○     ○○
```

- **介護職員・看護職員**は3:1判定の対象。看護職員は段階配置（入所者30以下1／30超50以下2／
  50超130以下3／130超は50ごとに+1）の判定も残す。看護不足は指定権者の指導対象になるため
- **その他職員**は原資を食う分としてまとめる。基準は施設長1・医師0.1・生活相談員1・
  機能訓練指導員1・介護支援専門員1・管理栄養士1の合計を自動計算し、内訳は注記で示す
- 基準常勤換算は定員・稼働率から自動計算（v0.4 と同じ）
- **正規・非正規・派遣の初期値は、基準と同じ値を正規に入れる**（非正規・派遣は0）。
  そこから施設の実情に応じて手入力してもらう

## 2. 派遣職員の扱い

社会福祉法人会計基準では**派遣職員費は人件費の中科目**である。
したがって給与原資の配分対象に含まれ、配置基準の判定にも算入される。

**STEP2の入力を1つ増やす。**

```
年間人件費総額（法定福利費込み）    ○○ 万円
　うち派遣職員費                    ○○ 万円   ← 内数
```

正規・非正規を金額で分けて尋ねる必要はない。人数は職種表で入るため、
金額側は「職員分」と「派遣分」の2つで足りる。

**計算**

```
職員給与原資 ＝（人件費総額 − 派遣職員費）÷（1 + 法定福利費率）
派遣費用     ＝ 派遣職員費（法定福利費の割り戻しをしない。派遣会社が負担するため）
```

**分子と分母を必ず揃えること。** 派遣費が分子に入っているのに派遣の人数を分母から
外すと、1人あたりが実態より高く出る。80床で派遣5人なら分母が53人か48人かで
1割の差が生じ、賃金水準を読み違える。

## 3. 横軸を人数空間（常勤換算数）にし、配置比率を併記する（バーとグラフを統一）

> 改訂（2026-07-28）。段階2で一度「横軸＝配置比率」にしたが、比率を横軸にすると
> **等原資曲線 給与原資÷n の双曲線が視覚的に失われる**ことが実測で判明した。比率 R と
> 職員数 n はほぼ反比例（n ≒ 入所者数÷R ＋ その他職員）のため、原資÷n を R に対して描くと
> 反比例が打ち消され、その他職員が0なら完全な直線になる。よって横軸は人数空間に戻す。
>
> 実測（画面上の傾きの左端付近/右端付近の比）：人数軸 7.02倍（はっきり曲がる）／
> 配置比率軸 0.75倍（ほぼ直線）／その他0のとき 比率軸 1.00倍（完全直線）・人数軸 9.33倍。
>
> ※この実測は指標がまだ B（給与原資÷n）だった時点のもの。**その後 決定②で A（人件費総額÷n）に
> 一本化した**が、どちらも n の反比例なので「人数軸なら曲がる／比率軸なら直線化する」という
> 結論は変わらない。以降の本文で「給与原資÷n」とあるのは当時の記録。

**職員数バーもグラフ横軸も人数空間（常勤換算の職員数 n）にする。** 曲線は 人件費総額÷n の
双曲線として描く（当初は給与原資÷n としたが、決定②で指標をAに一本化）。段階2で作った「つまみ位置とグラフ点を同じ割合 f から算出する」構造は維持し、
f を人数空間で定義する（→ INV-26 は人数空間で一致）。

**横目盛りは配置比率と常勤換算数を上下2段で併記する。**

```
上段：4.0:1 / 3.5:1 / 3.0:1 / 2.5:1 / 2.0:1 / 1.5:1 / 1.2:1 / 1.0:1
下段：それぞれに対応する常勤換算数（職員数 n）
```

- 目盛り間隔が不均等になるのは**正しい**。手厚くするほど1段階のコスト（職員数の増分）が
  増えることが、間隔の詰まり方（薄い側で詰まり、手厚い側で広がる）で見える
- 表示範囲は 4.0:1 相当 〜 1.0:1 相当の職員数。基準割れ側（4.0:1〜3.0:1）も見える
- 3.0:1 に対応する職員数の位置に基準線を引き、そこから左（薄い側＝職員少）を淡く塗る
- 薄い端で目盛りラベルが詰まって重なる場合は、左から貪欲に最小間隔をあけて間引く
  （基準線と両端は残す）

これによりバーとグラフが同じ人数目盛りになり、v0.4 で起きた
「バーは右端なのにグラフの点は中途半端な位置」という不一致が構造的に消える。

**ドラッグの反映先**

増減は介護職員・看護職員に反映される。**その他職員は動かない。**
「基準1.0の施設長が1.8人になる」問題は起きない。介護と看護の配分は、現在の構成比を保って按分する。
（人数軸の目標職員数 n はエンジンで配置比率 R＝a/(n−その他職員) に戻してから核だけ按分する。）

## 4. 縦軸は A の1本に一本化する（B は削除・2曲線は実装しない）

> **2026-07-28 決定②：指標を A に一本化し、B を削除する。** B（職員給与原資÷職員（正規＋非正規））を
> 採用すると、派遣がいる施設で「バー（例 70.9人）＝正規＋非正規＋派遣」と「グラフ（例 68.6人）＝
> 正規＋非正規」が食い違って見える。計算はどちらも正しいが、同じ「人」の単位で違う母集団を並べると
> プログラムの誤りに見える。これを避けるため、**画面の指標・軸・人数をすべて A と職員数（fteAll＝
> 正規＋非正規＋派遣）に統一する。**
>
> - **1人あたり給与費（A）＝ 人件費総額 ÷（正規＋非正規＋派遣）。** 分子に派遣費・事業主負担を含むので
>   分母にも派遣を含めて揃える。派遣0では自動的に正規＋非正規になり、場合分けが不要（→ INV-22/23）。
> - **グラフ縦軸＝A、横軸の職員数＝fteAll。** バーとグラフの人数が一致し、食い違いが構造的に消える（→ INV-04/UI-17）。
> - **賃金下限は額面のまま入力**（求人票と同じ土俵）し、比較のときだけ内部で **×(1+法定福利費率)** して
>   A軸上の位置に線を引く。線のラベルは「賃金下限 440万円（事業主負担込み 512.6万円）」と併記する（→ UI-18）。
> - **派遣1人あたり費用（派遣職員費÷派遣人数）は残す**が、「年収」ではなく「費用」であることを明示する。
> - B（額面 職員1人あたり）と、それに紐づく月例給・賞与月数入力は削除した。
>
> **2026-07-28 決定①：2本の曲線は実装しない。** 配置比率を横軸にすると双曲線が直線化し（§3改訂）、
> A・B の2本を重ねるとグラフが読みにくくなるため、グラフには2本目の曲線も推移の点も引かない。
> トレードオフの両面は §7 推移の下の「同じジレンマの両面」（5年後の2枚のカード）で数値として示す。
> 以下は当初案（AとBの2曲線）の記録として残す。

同じ縦軸（万円）に2本。

```
A：1人あたり給与費        ＝ 人件費総額 ÷（正規＋非正規＋派遣）
　　分子・分母とも派遣を含む。決算書・経営概況調査と同じ土俵の経営指標

B：職員1人あたり給与費（額面） ＝ 職員給与原資 ÷（正規＋非正規）
　　派遣を分子・分母から除く。求人票・賃金センサスと同じ土俵の賃金水準
　　正規と非正規で金額を分けない（第9節）
```

**2本の間隔について（設計時に一度誤った箇所）。**
当初「間隔＝派遣の影響量」と考えたが誤り。AとBは基準が違うため、
派遣がゼロでも一致しない。

```
派遣0のとき　A ÷ B ＝ 1 + 法定福利費率　（例：16.5% なら常に 1.165 倍）
```

実測（特養80床・人件費24,800万・派遣0）：3.0:1 で A=807.8万／B=693.4万（差114.4万）。
この差はすべて事業主負担であって、派遣とは無関係である。

したがって2本の間隔は「事業主負担＋派遣の効果」の合成であり、
派遣の影響量としては読めない。**そう説明しないこと。**

- **賃金下限の線はBに対して引く。** 守るべきは職員本人の賃金水準であるため
- Aは事業主負担込み、Bは額面。凡例でこの違いを必ず明示する
- 派遣の影響は、次の別指標で示すほうが正確
  - 派遣1人あたり費用 ＝ 派遣職員費 ÷ 派遣人数
  - 職員1人あたり人件費 ＝（人件費総額 − 派遣職員費）÷ 職員数
  この2つを並べれば、派遣が自前より高いか安いかが直接わかる

## 9. 非正規の賃金水準（係数70%）は削除する

v0.4 では「正規の平均年収 × 70%」で非正規の年収を出していたが、**削除する。**

人件費総額の中に正規・非正規の給与費がいずれも含まれているため、
常勤換算職員数が正しければ 1人あたり給与費は割り算で出る。
未検証の係数を挟む必要がない。

```
1人あたり給与費（A） ＝ 人件費総額 ÷（正規＋非正規＋派遣）   ← v0.5 決定②で A に一本化
派遣1人あたり費用     ＝ 派遣職員費 ÷ 派遣人数（賃金ではなく費用）
```

**正規と非正規を金額で分けない。** 分けるには内訳を尋ねるしかなく、入力が増える。

正規・非正規を人数で分ける意味は残る。配置基準の判定には両方が算入され、
正規比率そのものが人事考課・賃金制度の議論で使う指標になるため。
金額の按分に使わない、というだけである。

> **2026-07-28 追記（決定②）。** 当初は「職員1人あたり給与費（額面）＝（人件費総額−派遣費）÷（正規＋非正規）」
> ＝ B を額面指標として残す想定だったが、B（分母＝正規＋非正規）と 配置・グラフの職員数（分母＝
> 正規＋非正規＋派遣）が食い違って見えるため、**B は削除し、A（人件費総額÷職員数・派遣込み・事業主
> 負担込み）に一本化した。** B に紐づく月例給・賞与月数入力も削除。賃金下限（額面）は A軸で比較するとき
> ×(1+法定福利費率) して線を引く（第4節）。

## 11. 案B：横軸は職員数に統一し、配置比率は基準のあるサービスでのみ併記（2026-07-28 実装）

**通所介護には対利用者の比率基準が存在しない。** 介護職員は「利用者15人まで1以上、15人を超える
部分は5人ごとに1を加えた数」を提供時間帯を通じて配置する規定で、常勤換算は営業日数と提供時間に
左右される。特養の3:1のような比率の形をしていない。にもかかわらず横軸を比率で刻んでいたため、
15.4:1 等の意味のない目盛りが出て、基準線も引けない（凡例だけ残る）状態だった。

### 各サービスで比率基準が成立するか

| サービス | 法令上の人員基準 | 比率基準 | 画面の扱い |
|---|---|---|---|
| 特養（従来型） | 介護・看護の総数が入所者3:1以上＋看護は段階配置 | **成立** | 比率を併記・基準線3:1 |
| ユニット型 | 同上3:1＋ユニット常時配置 | **成立**（3:1は必要条件） | 同上 |
| 老健 | 看護・介護の総数が3:1以上。**うち看護2/7・介護5/7は「標準」（目安）** | **成立** | 同上（下記の注記つき） |
| 通所介護 | 利用者15人まで1、超過5人ごとに+1（提供時間帯を通じて）＋看護1以上 | **不成立** | **比率を出さない** |

### 実装

- 横軸は全サービスとも職員数（fteAll）。比率基準の有無は `hasRatioStd(c)` で判定する。
- **比率基準なし（通所）で出さないもの**：上段の比率目盛り／**比率の**基準線／
  比率スライダーのラベル（「職員数 ◯人」を主表示）／chartnote の比率・基準割れ文言／
  両面カードの比率行（減る人数で表示）／グラフ点ラベルの比率／**指標バーの比率セル**／
  **書き出しテキストの配置比率行**。
  （凡例の帯の文言は §16 でサービス共通に戻した。）
- **通所の軸域**は「**核（介護・看護）の基準を 0.75倍〜3倍**にした職員数」に固定する
  （＝`核std×0.75＋その他std` 〜 `核std×3＋その他std`）。2026-07-28 に ×0.85〜×2.0 から拡張。
  ★当初案の nMinComp（今の構成で基準を満たす最小）はアンカーに使えない。nMinComp は
  `max(std/行合計)` で現在の職種構成に依存するため、核だけを動かすドラッグで値が変わり、
  **軸が動いてしまう**（「軸域がドラッグで動かないこと」と両立しない）。stdN は定員・稼働率だけで
  決まる法令由来の値でドラッグ不変なので、こちらをアンカーにする（閾値の発明ではない）。
- 充足判定は従来どおり職種別基準（15人まで1・超過5人ごとに+1）で行う。変更なし。
- 老健の注記を caveat に追加：「うち看護2/7・介護5/7は標準（目安）で、行別判定はこれに基づく」。
  合計3:1を満たしていても配分が標準と異なると行別で不足と出ることがある旨を明示。

### 指標バー・書き出しの比率も出さない（2026-07-28 水田さん判断で追補）

当初は指標バーの比率セルを記述統計として残していたが、**通所では出さない**ことに決定した。理由：

1. グラフから比率を消したのは「通所介護に対利用者比率の基準が存在しない」ため。**同じ理由が
   指標バーにも当てはまる。** 基準がないのに数字だけ出すと、見た人は比較先を探すが比べる相手がない。
2. 他サービスでは同じ位置の同じセルが**基準との比較**（「基準 3:1 の 1.00 倍の手厚さ」）に使われる。
   同じ場所の同じセルがサービスによって意味を変えるのは、**「同じ名前で違うものを指す」問題と同じ型**。

同じ理由から、**書き出しテキスト（相談用）の配置比率行も比率基準のあるサービスに限る**
（数字だけが文脈から切り離されて独り歩きするのを防ぐ）。AXB-01 で両方を固定。

### テスト

AXB-01（通所で比率目盛り・基準線・凡例・比率スライダーを出さない）／AXB-02（通所の軸域が
ドラッグで動かない＝目盛りとアンカーが不変・同じつまみ位置で職員数が再現）／
AXB-03（特養・ユニット・老健で従来表示を維持）。

## 14. 通所の軸域を特養系と同じ幅に広げる（2026-07-28）

### 直した問題

軸域が `stdN×0.85〜×2.0` だった。**左端が基準の0.85倍**しかなく、基準を大きく割る領域が
見えない。0.85 という係数にも根拠がなかった。特養系は 4.0:1〜1.0:1 で基準3:1を大きく割る側まで
見えるため、通所だけ検討の幅が狭かった。

**判断の根拠（水田さん）**：基準ちょうどまでしか見えないと、そこで検討が止まる。
「これ以上薄くできないなら、賃金を上げるには稼働率か収入を動かすしかない」という判断に
つなげるため、基準を割る領域も見える必要がある。

### 採用した範囲と、その導出（係数を発明していないこと）

比率基準のあるサービスの軸は 左端 R＝基準+1／右端 R＝1。核は `core(R)＝利用者÷R` なので、

```
左端の核 ＝ 基準/(基準+1) 倍 ＝ 3/(3+1) ＝ 0.75倍
右端の核 ＝ 基準/1 倍       ＝ 3倍
```

**この 0.75〜3 は基準3:1のサービスで共通**（実測で特養・ユニット・老健とも一致）。
通所も同じ核倍率にすれば、基準を割る側も同じ深さ（25%薄い）まで見える。
→ `nmin = 核std×0.75 ＋ その他std`、`nmax = 核std×3 ＋ その他std`。

**stdN に直接倍率を掛けない理由**：その他職員まで一緒に増減させることになる。
ドラッグは核しか動かさない（その他は固定）ので、軸の端も核の増減で定義するのが対応する。
実測の stdN 倍率は 特養0.79〜2.67／ユニット0.73〜2.47／老健0.79〜2.66／通所0.83〜2.36 と
サービスごとに違うが、これは その他職員の比率が違うためで、**核倍率で揃えるのが正しい対応**。

### 制約の充足

| 制約 | 結果 |
|---|---|
| ゼロ除算が再発しないこと | 左端でも核は基準の**0.75倍（>0）**。端点を連続80回踏んでも核0・Infinity・NaN なし |
| 軸域がドラッグで動かないこと | 核std・その他std はどちらも定員・稼働率だけで決まりドラッグ不変。目盛り文字列の一致で確認 |
| 特養系の表示は変更しない | 軸（24.3〜81.9／29.2〜98.2）・比率目盛り7点・基準線1本とも変更なし |

実測（通所・定員35/稼働88%）：軸 6.72〜19.10（旧 6.88〜16.20）。左端の核 4.13人＝基準5.5人の75%。
基準の単純合計 8.1人を左端が下回り、基準割れの領域が見えるようになった。

テスト：**AXB-04**（左端が基準の単純合計を下回る／左端の核が基準の0.75倍かつ>0／右端が3倍／
端点を連続80回踏んでも異常なし／特養系も核0.75〜3倍で一致）。変更前のコミットで落ちることを確認済み。
AXB-02（軸不変）・AXB-03（特養系不変）・ZERO-01（端点連続）は維持。

## 15. 人数ベースの基準マーカー（2026-07-28）

### 追加した理由

§14 で通所の軸を基準より左（核0.75倍）まで広げたが、**境界が見えないと広げた意味が半減する**。
「基準を割る領域を見せて、そこから稼働率や収入の検討につなげる」のが目的だったため、
どこからが基準割れかを示す必要がある。また、特養系には3:1の基準線があるのに通所だけ境界が
見えないのは表示として非対称だった。

### 実装

- **比率基準の無いサービス（通所）**：`nbase = stdN`（**基準の単純合計＝各職種の基準の合計**）の位置に
  縦の基準マーカーを引き、ラベルは「**基準 8.1人**」。左側（基準を下回る領域）は従来どおり淡く塗る。
  stdN は法令由来の各職種基準の合計なので、**閾値の発明ではない**。
- ラベルは比率基準の有無で分岐する（比率あり→「基準 3 : 1」／なし→「基準 ◯人」）。
- 凡例の「基準線」は**常に表示**する（比率あり＝比率の基準線、なし＝人数の基準マーカー）。
  §11 で「引けない基準線は凡例から消す」としていたが、引けるようになったので戻した。
- 通所の chartnote から「基準線は表示しません」を削り、
  「縦の基準線は基準の単純合計の位置で、そこから左は基準を下回る領域」と説明を加えた。

### 特養系の扱い（重複の検討・結論）

**特養系には人数マーカーを追加しない。既存の比率基準線のみとする。** 理由：

1. 初期状態では**両者がほぼ同じ位置**になる（特養：3:1線＝利用者÷3＋その他＝30.7、stdN＝25.6＋5.1＝30.7）。
   2本引くと「どちらが基準か」が曖昧になる。
   ※厳密には一致しない。3:1線は**現在の**その他職員数を使い、stdN は**基準の**その他を使うため、
   その他を基準から増減させるとずれる。ずれた2本を並べるのはかえって誤読を招く。
2. 特養系では**比率要件が法令上の主たる基準**であり、比率で示すのが自然。
3. 人数の基準合計は**指標バー「基準合計との差（基準 30.7 人に対して）」**で既に出ている。
4. 案B（比率基準のあるサービスは比率で示す）の整理と整合する。

### テスト

- **AXB-05**：通所で基準マーカーがラベル「基準 ◯人」で出る／位置が基準の単純合計に対応する／
  **定員を変えて軸域が変わってもマーカーが追従する**／ドラッグでは動かない（基準は実配置に依存しない）。
- **AXB-06**：特養・ユニット・老健は基準ラベルが比率のままで、人数マーカーが混ざらず、縦線は1本のみ。

  固定する形に変更。凡例の基準線は表示される前提に更新。
- AXB-02（軸不変）・AXB-03（特養系の表示不変）・AXB-04（軸域）は維持。

## 16. 緑の帯を基準で切る／凡例の語を整理（release-gate 第3回 H1 への対応・2026-07-28）

### 直した問題（H1・P2）

緑の太実線は「**ここなら成立する**」区間を表す。ところが比率基準の無いサービス（通所）では
**基準による切り出しをしておらず、賃金下限だけで帯を引いていた**。§14 で軸を基準の左まで
広げたため、**基準を割った領域まで帯が伸びて「そこも成立する」と読める**状態が顕在化した。

```
比率基準あり → 配置比率が基準以下（R <= 基準）
比率基準なし → 職員数が基準の単純合計以上（n >= nbase）
```

> **※この「n >= nbase」は §17 で一度 `nMinComp` に置き換えたが、§18 で元に戻した**

`seg()` のコールバックに職員数 `n` を渡すようにして判定できるようにした。
（修正案2「帯は変えず凡例と説明で限定する」は、画面内の矛盾が残るため採らない。）

### 凡例の整理（P3・同時実施）

**サービスによらず、同じ意味の要素は同じ語で呼び、違う意味の要素は語を分ける。**

| 要素 | 方針 | 結果 |
|---|---|---|
| 緑の帯 | どのサービスでも**同じ意味** → **同じ語** | 全サービス「基準内かつ賃金下限を満たす区間」 |
| 基準の縦線 | **意味が違う**（配置比率の基準／人数の基準） → **語を分ける** | 比率あり「基準線（**配置比率**）」／なし「基準線（**人数**）」 |

§11 で「通所の凡例の帯は『賃金下限を満たす区間』にする」としていたが、帯が基準で切れるように
なったので**共通の文言に戻した**。

## 17. 帯の判定を nMinComp に／凡例に破線と塗りの読み方を追加（release-gate 第4回 I1・指摘J）

### 17.1 直した問題（I1・P2）

§16 で帯を基準で切るようにしたが、比率基準の無いサービスの条件が
`n >= nbase`（**合計人数 ≧ 基準の単純合計**）だった。これは **caveat でツール自身が否定している判定方法**：

> 3:1などの配置基準は**職種別の要件**です。事務や調理を厚くすれば合計人数を満たしたまま
> 介護・看護が基準を割るため、**合計の下限だけでは判定できません**。

実測（通所・介護2.0／その他6.0＝合計9.1・基準合計8.1以上）：充足判定は「下回っています」なのに
点は帯の内側（x=170.3、帯 128.6〜234.8）。**H1 と同型の矛盾が職種構成の偏りという別経路で残っていた。**

### 17.2 採用した判定（修正案1）

```
比率基準あり → 配置比率が基準以下（R <= 基準）  ← 法令上の必要条件として AND で残す
すべて共通  → 職員数 n >= nMinComp（いまの職種構成のまま人数を増減させたとき
                                   全職種が基準を満たす最小の合計）
基準のある職種が0人（blocked）→ nMinComp=∞ で帯は出ない
```

`nMinComp` は**職種別の判定を人数に翻訳した値**なので caveat と一致する。

**★重要な性質**：現在地では `充足 ⟺ n >= nMinComp` が**厳密に成り立つ**
（`nMinComp = fteBase×sMin`、`充足 ⟺ sMin<=1 ⟺ nMinComp<=fteAll=n`）。
したがって**点が帯の内側かどうかと、充足判定パネルの結論は必ず一致する**。
帯の左端は職種構成に応じて動くが、これは「構成が変われば必要な最小合計も変わる」ため正しい
（軸は固定のまま）。

### 17.3 境界のサンプリング（実装上の落とし穴）

帯は曲線を等間隔（121点）でサンプリングして描いていたため、**条件が切り替わる境界が
サンプル点に乗らず、帯の端が最大1サンプル分（約4.6px）ずれていた**。
その結果、**基準ちょうどの配置＝起動時の初期状態で、点が帯からわずかに外れて見えていた**
（特養：点 x=125.6 に対し帯の左端 x=128.6）。

対策：`seg()` のサンプル列に、条件が切り替わる n（`nMinComp`／賃金下限に対応する `total/floorA`／
`nbase`）を**明示的に加える**。これで帯の端が境界に一致する。

### 17.4 凡例に破線と塗りの読み方を追加（指摘J）

軸を広げて「**見えるが成立範囲ではない**」領域を作った以上、その読み方を示す必要がある。

| 追加した項目 | 文言 | 意味 |
|---|---|---|
| 灰色の破線 | **同じ人件費で取り得る組み合わせ** | 人件費総額を変えずに動かせる範囲（基準の外も含む） |
| 淡い朱の塗り | **基準を下回る領域（成立範囲の外）** | 基準マーカーより左＝職種別基準を満たさない |

塗りの見本は線ではなく面なので、凡例に専用クラス `.legend i.sw` を追加した。

### 17.5 テスト

- **AXB-10**：**点が帯の内側かどうかと充足判定パネルの結論が必ず一致する**ことを、
  4サービス×10ケース（偏った構成・その他だけ薄い・基準のある職種が0人・**起動時の境界**を含む）で固定。
- **AXB-11**：凡例に破線・塗りの読み方があり、塗りの見本が面であること。
- 2件とも**修正前のコミットで落ちることを確認済み**
  （AXB-10 は「充足=false なのに帯の内側=true」で失敗）。

## 18. I1 の撤回：帯は固定に戻し、caveat との差は開示で埋める（2026-07-28）

### 18.1 撤回の理由（水田さん判断）

§17 で帯の左端を `nMinComp` にしたが、**nMinComp は現在の職種構成に依存するため、
ドラッグで構成が変わるたびに帯そのものが伸び縮みする**。当初は帯が固定で、その中を点が動く形だった。
**道具としては固定のほうが使いやすい**ため元に戻す。

実装からは「帯の左端が職種構成に応じて動く挙動になる点は確認が要る」と申し送りをしていたが、
設計側が計算の正しさだけで採用し、操作感への影響を見落とした（水田さんの自己評価）。

### 18.2 現行の帯の条件（§16 に戻す）

```
比率基準あり → 配置比率が基準以下（R <= 基準）        ← AND で維持
共通         → 職員数が基準の単純合計以上（n >= nbase） ← 固定。ドラッグで動かない
共通         → 1人あたり給与費が賃金下限以上（A >= floorA）
```

※比率基準ありのサービスでは `nbase = 利用者÷基準＋その他` なので、`n >= nbase` は `R <= 基準` と同値。
実質、比率サービスは比率で、比率のないサービスは合計人数で切っている。

### 18.3 caveat との矛盾をどう埋めるか（3層で開示）

帯を合計で切る以上、caveat の「**合計の下限だけでは判定できません**」との差は残る。
**放置せず、次の3層で開示する。**

| 層 | 内容 |
|---|---|
| (1) 名乗りを実態に合わせる | 凡例を「基準内かつ賃金下限を満たす区間」→「**合計人数と賃金の目安（職種別は下の判定欄）**」に変更。帯が職種別の充足判定ではないことを、帯の名前自体が言う |
| (2) 説明で補う | chartnote に「**緑の帯は合計人数と賃金の目安です。**職種ごとの過不足（介護・看護・その他）は帯では見ていないので、充足の可否は下の判定欄で確認してください」を全サービス共通で追加 |
| (3) **矛盾が起きた瞬間に名指しする** | 点が帯の内側なのに職種別が未達のとき、グラフ上に朱色で「**合計は足りていますが、職種別の基準を満たしていません（下の判定欄）**」を出す（`data-o="gapwarn"`） |

(1)(2) は静的な開示、(3) は**状態依存**で、H1/I1 が問題にした「同じ画面が逆の合図を出す」状況が
実際に発生した瞬間にだけ出る。**これにより、帯が合計ベースでも画面が黙ったままにはならない。**

### 18.4 AXB-10 の扱い（テストの契約変更）

**削除せず、契約を書き換えた。** 帯が `nbase` になったことで
「点が帯の内側 ⟺ 充足判定パネルの結論」は**もはや成り立たない**（合計は足りるが職種別は未達、が帯の内側に入る）。
代わりに次の2つを固定する：

- **(a)** 点が帯の内側かどうかが、**帯が名乗っている条件**（比率・合計人数・賃金）と厳密に一致すること
- **(b)** 帯の内側なのに職種別が未達のときは、**グラフ上で名指しすること**
  ＝画面が逆の合図を出したまま黙っていないこと（H1/I1 の再発防止はこちらが担う）

`nbase` は比率サービスでは「利用者÷基準＋その他」で、その他の実配置に依存する点に注意
（テストの期待式もこれに合わせた）。**特養で その他だけ薄い構成**も (b) の対象になり、名指しが出る。

### 18.5 テスト

- **AXB-12（新規）**：**帯の左端がドラッグで動かないこと**（撤回の理由そのもの）。

## 19. 帯と「両立する区間なし」の矛盾（2026-07-28・自損バグの是正）

### 19.1 症状と原因

ユニット型・定員80・稼働96%・ユニット8 で、**緑の帯が描かれているのに、同じグラフに
朱色で「両立する区間なし」が同時に表示される**（実測では**全4サービス・初期状態で再現**）。

原因は判定条件のずれではなく、**`if` / `else` の結合先が壊れていたこと**である。
§18.3 (3) の `gapwarn` を追加したとき、帯を描く `if` と「両立する区間なし」の `else` の
**あいだに** 新しい `if` を割り込ませてしまった：

```js
if (okBand) 帯;                         // ← else が外れた
if (pointInBand && 未達){ gapwarn }
else if (c.atgt > 0) 「両立する区間なし」   // ← gapwarn の else になっている
```

結果、**gapwarn が出ない状態（＝ほとんどの正常な状態）で常に**「両立する区間なし」が出た。
帯の条件は正しく、表示の結合だけが誤っていた。

### 19.2 是正：条件を1つの関数に集約（E-008）

帯に関する量を**1か所でしか計算しない**形に直した。

```js
function inBand(R, y, n){ ... }              // ★帯の条件はここだけ
var okBand = seg(inBand);                    // 帯そのもの
if (okBand){
  帯を描く;
  if (inBand(c.ratioActual, c.avg, c.n) && 職種別未達) gapwarn;   // 点が帯の内側か
} else if (c.atgt > 0) noband;               // 帯が空のときだけ
```

- 従来は `pointInBand` が帯の条件式を**書き写して二重に持っていた**（E-008 違反）。関数呼び出しに置換。
- `gapwarn` を `if (okBand)` の内側に入れ、`noband` を `okBand` の `else` に戻した。
  **帯の有無という1つの値からしか分岐しないので、構造上、帯と noband は同時に出ない。**

### 19.3 「両立する区間なし」は残すか（意図の確認）

v0.3 から残っていた表示。**残す。ただし文言を変更した。**

- **いつ出るか**：帯が1点も引けないとき。帯の条件は n=nbase で比率・合計とも成立するため、
  帯が空になるのは実質**「基準どおりの人数を賃金下限で雇えない」場合に限られる**（A は n の減少関数）。
- **必要な理由**：帯が消えたとき、グラフには破線と塗りしか残らない。
  **緑が無い理由をグラフ側で言わないと画面が黙る**（実測：修正前は 120 ケース中 30 ケースで黙っていた）。
- **文言変更**：「両立する区間なし」→「**この賃金下限では、基準を満たす区間がありません**」。
  - 旧文言は判定欄の「この原資では両立しません」と同語で、**同じ判定に見える**。
    実際は物差しが違う（グラフ＝基準の単純合計 `nbase` ／判定欄＝職種別下限 `nmin`）。
  - 新文言は**理由（賃金下限）と対象（基準を満たす区間）**を言うので、判定欄と役割が分かれる。

## 20. 文言修正：入力欄の初期値の呼び方と、金額の期間単位（2026-07-29）

### 20.1 「未検証」を入力欄の初期値に使わない（分類①）

**判断基準**：入力欄の初期値は**検証の対象ではなく入力例**である。利用者が自法人の数値で
上書きする前提の欄に「未検証」と書くと、自社が検証責任を果たしていないという意味になる。
一方、**利用者が上書きしない既定値（②）と外部の水準を示す参考値（③）は従来どおり根拠・出典が要る**
（E-001／E-002 は引き続き有効。ここは緩めない）。

| 分類 | 対象 | 今回の扱い |
|---|---|---|
| ① 利用者が上書きする入力欄の初期値 | 年間収益・人件費総額・派遣職員費・下回れない平均年収 | **修正**（「入力例」と呼び、「未検証」を使わない） |
| ② 利用者が上書きしない既定値 | 法定福利費率 16.5％ | **触らず報告**（出所を1行で書けない。§20.4） |
| ③ 外部の水準を示す参考値 | 人件費率 64.3％ | 変更不要（出典が既にある） |
| 判断保留 | ユニット型の常勤換算前提「日中16時間・夜間8時間・週7日（未検証）」 | ①②③のどれでもない（ツールの計算前提）。§20.4 |

### 20.2 金額の期間単位「万円／年」

このツールの金額はすべて年額（決算書と同じ期間）。月額との混同を防ぐため単位に「／年」を含める。
**月換算は表示しない。**

- 単位は `man()` 1か所で持つ（全呼び出し先が年額であることを確認したうえで）。
- 手書きの「万円」（1人あたり給与費 A・賃金下限・事業主負担込み換算）は個別に「万円／年」へ。
- **付けない**：人数（常勤換算）／比率・ポイント／率（％）／年間上昇率。
- **例外**：`yen()`＝「1人1日あたり収入」は**年額ではない**（円／日）。ラベルに「1人1日あたり」と
  明記されているため今回は変更していない（§20.4）。

### 20.3 分母の明示（「いま動かすと何が起きるか」）

1人あたりの額と法人全体の額が同じ表に並ぶため、engine の式から分母を確認して見出しに書いた。

| 表示 | engine の式 | 分母 |
|---|---|---|
| 1人あたり給与費 −◯ 万円／年 | `total/n − total/(n+1)` | **1人あたり** |
| 必要な追加人件費 | `needMoreTotal = n × 10` | **法人全体**（職員数ぶんの積み上げ） |
| 収益増でまかなうなら | `revUp = needMoreTotal ÷ (人件費率/100)` | **法人全体** |
| 人員削減でまかなうなら | `cutN` | 人数（単位なし） |
| 人件費率で吸収するなら | `ptUp` | ポイント（単位なし） |

### 20.4 今回触らなかったもの（判断が要る）

1. **法定福利費率 16.5％（②）**：caveat に「健康保険・厚生年金・雇用保険・労災の事業主負担分の
   おおよその合計」という**構成の説明はある**が、16.5 という数値の算出根拠（年度・都道府県の実料率）は
   確認していない。**書けないので触らず報告**とした。
2. **ユニット型の常勤換算前提（日中16時間・夜間8時間・週7日）**：入力欄の初期値でも既定値でも
   参考値でもなく、**基準人数を出すための計算前提**。①②③のどれにも当てはまらないため判断保留。
3. **README「数値の検証状態（すべて未検証）」の表**：①に当たる行（年間収益・人件費総額の初期値）を
   含む。①だけ外すと表の見出し「すべて未検証」と整合しなくなるため、表の構成そのものの判断が要る。
4. **`yen()`＝1人1日あたり収入**：このツールで唯一の非年額（円／日）。「金額はすべて年額」という
   今回の前提の例外にあたる。
5. **§5・§6 の促し文の「初期値 400.0 万円はサンプルです。」**：指示の文言をそのまま採ったため、
   ここだけ金額に「／年」が付いていない。単位の一貫性としては未統一。
