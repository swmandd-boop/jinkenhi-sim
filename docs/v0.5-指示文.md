## 段階1 — 入力構造の作り直し（STEP2・STEP3）

```
docs/v0.5-設計.md を読んでください。v0.5 の実装を3段階に分けて進めます。
今回は段階1（入力構造）だけです。段階2・3には進まないでください。

■ 実装するもの

1. 職種表を3行にする（第1節）
   介護職員／看護職員／その他職員 の3行。
   各行に 正規・非正規・派遣 の3列。合計列は自動計算。

   - 介護職員・看護職員は3:1判定の対象。看護職員の段階配置判定も残す
   - その他職員の基準は、施設長1＋医師0.1＋生活相談員1＋機能訓練指導員1＋
     介護支援専門員1＋管理栄養士1 を自動計算。内訳は注記で示す
   - 正規・非正規・派遣の初期値は、基準と同じ値を正規に入れる（非正規・派遣は0）
   - 基準常勤換算は定員・稼働率から自動計算（v0.4と同じ）

2. STEP2に「うち派遣職員費」を追加（第2節）
   年間人件費総額の内数として尋ねる。

   職員給与原資 ＝（人件費総額 − 派遣職員費）÷（1 + 法定福利費率）
   派遣費用     ＝ 派遣職員費（法定福利費の割り戻しをしない）

3. 非正規の賃金水準（係数70%）を削除（第9節）
   人件費総額に正規・非正規の給与費が含まれているため、
   常勤換算職員数が正しければ割り算で出る。未検証の係数は挟まない。

   職員1人あたり給与費 ＝（人件費総額 − 派遣職員費）÷（正規＋非正規）
   派遣1人あたり費用   ＝ 派遣職員費 ÷ 派遣

   正規と非正規を金額で分けないこと。人数として分ける意味は残る
   （配置基準の判定と正規比率の表示に使う）。

4. 初期状態で 基準合計 = 正規合計 を厳密に一致させる
   現在0.1ずれています。

■ 重要な注意（第2節）

分子と分母を必ず揃えること。派遣費が分子に入っているのに派遣の人数を
分母から外すと、1人あたりが実態より高く出ます。
80床で派遣5人なら分母が53人か48人かで1割の差が生じます。

- INV-25 初期状態で 基準合計 = 正規合計 が厳密に成立
- LAYOUT 3行になった職種表で文字が欠けないこと
```

## 段階3 — 2本の曲線と診断

段階2を実機で確認してから。

```
段階3に進みます。docs/v0.5-設計.md 第4節・第5節です。

■ 1. 縦軸に2本の曲線（第4節）

  A：1人あたり給与費 ＝ 人件費総額 ÷（正規＋非正規＋派遣）
     事業主負担込み。決算書・経営概況調査と同じ土俵

  B：職員1人あたり給与費（額面）＝ 職員給与原資 ÷（正規＋非正規）
     派遣を分子・分母から除く。求人票・賃金センサスと同じ土俵

- 賃金下限の線はBに対して引く
- 凡例で「Aは事業主負担込み、Bは額面」を明示する

■ 重要（第4節の訂正箇所）

2本の間隔を「派遣の影響量」と説明しないこと。
AとBは基準が違うため、派遣0でも一致しません（A÷B ＝ 1+法定福利費率）。
間隔は事業主負担と派遣の効果の合成であり、派遣の影響量としては読めません。

派遣の影響は別指標で示すこと：
  派遣1人あたり費用     ＝ 派遣職員費 ÷ 派遣人数
  職員1人あたり人件費   ＝（人件費総額 − 派遣職員費）÷ 職員数
この2つを並べれば、派遣が自前より高いか安いかが直接わかります。

■ 2. 診断の中心（第5節）

「この原資なら何:1まで手厚くできるか」を主たる答えにする。

表示例：
  この原資なら 1.60 : 1 まで手厚くできます。
  それ以上は平均年収が 400 万円を割ります。

閾値を発明しないこと。基準3:1は法令、賃金下限は入力値です。

■ 仕上げ
- npm run dump を再実行して review/screen-dump.txt を更新
- README と docs/v0.5-設計.md を実装に合わせる
- 版数を v0.5 に

完了条件：npm run check が通り、ローカルコミットまで。push はしない。
報告は review/v0.5実装報告.md に書き、チャットにはパスと要点だけ。

■ 報告の書き方
検証していないことを「完了」「網羅」と書かない。
テスト件数・探索件数は実際の出力をそのまま転記する。丸めない。
未検証のサンプル値（法定福利費率・賞与月数・収益/人件費の初期値・
人件費率の参考値64.3%）は変更していないことを明記する。
```
