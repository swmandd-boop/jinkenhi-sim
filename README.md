# SWMD 人件費トレードオフ・シミュレーター v0.5

福祉施設の人件費原資に対して、職員配置（常勤換算）と賃金水準が同時には決められないことを、
サービス種別の人員配置基準と突き合わせて確認するツール。

## このリポジトリの構成

```
index.html                 本体。単一HTML・外部通信なし。これをそのまま公開する（URLは .../jinkenhi-sim/ で済む）
engine.mjs                 自動生成。編集しない（index.html から抜き出したもの）
tools/extract-engine.mjs   本体の ENGINE 区間を engine.mjs に抜き出す
tools/dump-screen.mjs      画面の全表示値をテキストに書き出す（adversarial-review モード2用）
tests/helpers.mjs          テスト用の入力生成とUI操作の再現
tests/invariants.test.mjs  計算層の不変条件（INV-01〜27・DIL-01〜03・RKN-01・KANGO-01・STEP2）
tests/ui.test.mjs          画面の矛盾検出（UI-01〜15・INV-26・AXIS-01・実バグの回帰を含む・jsdom）
tests/initial-roster.test.mjs 起動直後の基準配置の回帰（INIT-01/02）
tests/layout.test.mjs      実ピクセルのレイアウト検査（ヘッドレスChrome・欠け／右余白／2段目盛り／両面カード）
tests/explore.mjs          ランダム入力の探索テスト（既定 10,000 ケース）
review/screen-dump.txt     自動生成。レビュー材料
docs/v0.5-設計.md          v0.5 の変更仕様と実装状況（実装の正本）
docs/v0.4-設計.md          v0.4 の変更仕様（履歴）
```

`tests/layout.test.mjs` は jsdom では測れない実ピクセルの欠け・右余白・横スクロールを、
ヘッドレス Chrome（`puppeteer-core`＋システムChrome）で複数のウィンドウ幅を描画して検査する。
Chrome の場所は `CHROME_PATH` で上書きでき、見つからなければ失敗する（構成担保テストでは
実ピクセルの代替にならないため、この機械チェックを必須ゲートとする方針）。

## 設計の約束（守らないとテストが機能しなくなる）

本体HTMLは2つの区間に分かれている。

- `/* ===== SWMD-ENGINE:BEGIN ===== */` 〜 `:END`
  **DOMに触れない純粋な計算層。** 入力オブジェクトを受け取り、画面に出す全数値を返す。
  この区間に `document` / `window` / `getElementById` を書いてはいけない。
  `tools/extract-engine.mjs` がガードしており、混入すると build が失敗する。

- `/* ===== SWMD-UI:BEGIN ===== */` 〜 `:END`
  DOM層。入力を集めて `ENGINE.calcState()` に渡し、返り値だけを描画する。
  **この層に計算式を書いてはいけない。** 書いた分はテストの網から外れる。

単一HTMLのままである理由は、GitHub Pages にそのまま置ける／オフラインで動く／
施設の環境で外部通信を伴わないこと。ビルド成果物を配布物にしない。

## 使い方

```bash
npm install          # jsdom＋puppeteer-core（レイアウトの実ピクセル検査に使う）
npm test             # engine 抜き出し → 不変条件・UI・回帰・レイアウト（計38件）
npm run explore      # ランダム10,000ケースの探索テスト
npm run layout       # レイアウトのみ（ヘッドレスChromeで実ピクセル検査）
npm run dump         # review/screen-dump.txt を生成
npm run check        # test + explore
```

`npm test` はレイアウト検査（`tests/layout.test.mjs`）を含むため **Google Chrome が必要**。
場所は `CHROME_PATH=/path/to/chrome npm test` で上書きできる。

`npm run explore 50000 12345` のようにケース数とシードを指定できる。
違反が出た場合は、再現用の入力オブジェクトがそのまま標準エラーに出力される。

## v0.5 の変更（2026-07-28・`docs/v0.5-設計.md`）

- **職種表を3行に**（§1）：介護職員・看護職員・その他職員 × 正規・非正規・派遣の9マス。その他は
  施設長・医師・生活相談員・機能訓練指導員・介護支援専門員・管理栄養士の基準を自動合算（不足時は内訳表示）。
- **派遣職員費を人件費総額の内数に**（§2）：職員給与原資＝(総額−派遣費)÷(1+法定福利費)。派遣費は
  法定福利費を割り戻さない（派遣元負担）。A＝総額÷(正規+非正規+派遣)／B＝原資÷(正規+非正規)で分子分母を揃える。
- **非正規の賃金水準係数70％を削除**（§9）：正規・非正規は人数だけ分け、金額は分けない。
- **グラフ横軸を人数空間（常勤換算の職員数）に統一**（§3）：曲線は原資÷nの双曲線。上段=配置比率
  （4.0:1〜1.0:1）／下段=常勤換算数 の2段目盛りを併記し、3:1に基準線。バーとグラフ点は同じ割合で一致。
  ドラッグは介護・看護のみに反映（その他は固定）。
- **「同じジレンマの両面」**（§4の代替）：推移表の下に、5年後に「人数を保つ（率が上がる）」か
  「率を保つ（人が減る＝配置が薄くなる）」かの2枚を数値で並べる（g>0のときのみ）。
  **2本の曲線・診断文（当初の段階3）は実装しない**（グラフが読みにくくなるため）。

## v0.4 の変更（2026-07-27・`docs/v0.4-設計.md`）

- **職種別の基準年収を廃止**（§1）。集計値（平均年収・人件費率・総額・原資）は職種間の
  配分に依らないため。賃金倍率・fit-wage・表の年収3列も削除。
- **平均年収の再定義**（§2）：`avgSe = pool/(nSe+hw·nHi)`、`avgHi = avgSe·hw`。
  **注意：正規/非正規の平均年収は、v0.3（基準年収で加重）と非一様な混在ロスターで
  値が変わる**（全体平均・total・pool は不変）。承認済みの仕様変更。
- **新機能A 必要人件費率**（§5）／**B 定点の位置づけ**（§6・起動時の「基準ちょうど」を
  診断が名指し）／**C 推移**（§7・年上昇率 g で 3/5/10年、既定 0.0％）。
- **STEP2「原資を決める」の作り直し**（§11）：入力を「年間サービス活動収益」「年間人件費総額」の
  2つ（どちらも決算書の実額）に限定。人件費率は割り算で**出力**し、参考64.3％と比較（率入力の
  循環を解消）。1人1日あたり収入も出力へ。単価入力・autoRev・率入力・モード切替を削除。

## 既知の限界

- 月例給は年収÷(12＋賞与月数)の単純換算。夜勤手当・時間外・通勤手当を分離できない
- 職員1人あたり給与費は原資÷人数で、職種ごとの賃金差を入れていない。v0.5では正規・非正規を金額で分けない（人数のみ分ける）
- 事業主負担率は全職員一律で計算している（非正規の短時間勤務等での実負担差は未反映・入力簡素化のため）
- 派遣職員費は人件費総額の内数として扱い（社福会計基準の人件費中科目）、法定福利費の割り戻しはしない（派遣元が事業主負担を持つため）
- 処遇改善加算を収益・人件費から分離していない（決算書からは切り分けられないため）
- 常勤換算数と実人数は別。シフト成立性・夜勤体制・有給取得は判定していない
- 推移は収入横ばい・現行の賃金カーブ維持が前提。介護報酬改定・処遇改善改定・稼働率変動は非計上
